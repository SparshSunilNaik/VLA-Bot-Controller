Drive the plant doctor

VLA-Bot-Controller runs a Raspberry Pi farm rover: a Flask server on port 9999 nudges two DC motors in 0.3 second steps, two relay valves spray blight or mold treatment, and a ResNet-18 knows 38 leaf conditions. This page runs the same logic in your browser. Go cure some tomatoes.

Every click buys 0.3 seconds

The web pad never says "go until I let go". Each press runs the motors, then a daemon thread sleeps 0.3 s and stops them, unless a newer press has bumped the step counter first. Drive above and watch the tape.

def execute_step(action_name):
    with step_lock:
        current_step_id += 1
        this_id = current_step_id
    ...  # motors on

    def delayed_stop(step_id):
        time.sleep(STEP_DURATION)   # 0.3
        with step_lock:
            if current_step_id == step_id:
                ctrl.stop()          # only the newest step stops

    threading.Thread(target=delayed_stop,
                     args=(this_id,), daemon=True).start()

Why it feels smooth

Press faster than 0.3 s and each new step steals the stop from the one before, so the motors never pause. Press slower and you get little hops with gaps in between. A dropped connection can never leave the rover driving off on its own.

The catch

ctrl.stop() stops everything, pump and valves included. Tick the quirks box above, hold a spray and tap forward: the spray dies 0.3 s later.

Live pin board

Every GPIO the code touches, on a real 40-pin header. Pins light up as you drive and spray. Pick a part to see its wiring.

03

Leaf doctor

vision/detector.py loads a fine-tuned ResNet-18 with a 38-way head and the PlantVillage labels from classes.json. Pick a leaf and step through what it does to the picture.

The scores are made up in your browser to show the shape of the output; the 43 MB finetuned_resnet.pth doesn't run here. In the repo the detector isn't wired into the server yet, and spraying stays a human decision.

04

Plug in a controller

ps5_controller.py polls a DualSense with pygame 20 times a second. Connect any gamepad to this page and it drives the rover above with the same mapping.

No gamepad yet. Plug one in and press any button.

    Unlike the web pad, the stick calls the motor methods directly with no step timer, and a centred stick calls stop() on every poll. Browsers number buttons with the standard mapping, so the PS button is 16 here and 12 in pygame.

        06
        
    Run it on a real Pi
    
        
    Raspberry Pi with an L298N, two DC motors, a pump and two solenoid valves on relays. Optional: a DualSense paired over Bluetooth and a USB camera.
    
      
    
      
    
        
    
          
    Grab it
    
          
    Make a fresh environment on the Pi. The committed rover_env/ belongs to another machine.
    
          
    git clone https://github.com/SparshSunilNaik/VLA-Bot-Controller.git
cd VLA-Bot-Controller
python3 -m venv .venv
source .venv/bin/activate
pip install flask flask-cors gpiozero lgpio pygame
    
        
    
        
    
          
    Start the server
    
          
    Then open the Pi's address on port 9999 from any phone on the same network.
    
          
    python3 server.py
# open http://<pi-ip>:9999
    
        
    
        
    
          
    Or go local
    
          
    A fullscreen PyQt5 touch panel with hold-to-drive buttons, plus quick hardware checks.
    
          
    python3 main.py        # touch GUI
python3 test_relay.py  # pump + valves
python3 verifycam.py   # camera
    
        
    
      
    
      
    
        
        
    
          Good to know before you wire it up
          
      
            
    • requirements.txt is a whole ROS 2 environment with editable installs from someone's home folder, so the short pip line above is the easier route.
      • 
            
    • The relays are active low: the code drives the pin LOW to switch a valve on.
      • 
            
    • The pin numbers in config.py don't all match the ones in the code. The pin board above follows what the code actually opens.
      • 
            
    • The README lists /api/status as POST. The server only answers GET.
